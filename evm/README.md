# ZK-gated settlement on QoreChain's EVM

`PayoutGate` pays a fuel station for a day **only** if it presents a valid zero-knowledge proof that the day's figures reconcile (see `zk/`). The chain never sees a single figure.

- **`contracts/ReconcileVerifier.sol`:** Groth16 verifier for the reconciliation circuit, using the BN254 precompiles. It's generated by `scripts/gen-verifier.mjs` from `zk/build/verification_key.json` (Apache-2.0).
- **`contracts/PayoutGate.sol`:** checks that the proof's station-day id matches the claim, that the public signal says `reconciled = 1`, that the day hasn't been paid, and that the proof verifies. It then pays 0.1 QOR to the station's registered payee. Anyone can relay a claim, but only the payee receives the money.

## Tests (local, Hardhat)
`npm test` runs 8 tests with real proofs:
- a reconciled day is paid once;
- the theft day (a valid proof that says `reconciled = 0`) is refused with `NotReconciled`;
- a forged `reconciled` flag is refused with `InvalidProof`;
- replaying a proof for another day, paying twice, an unknown station and registration by a non-owner are all refused.

One claim costs about 301k gas.

## Testnet
```
npm install          # also run npm install in ../zk (the prover)
npm run compile
npm run deploy       # derives the EVM identity from QORE_MNEMONIC, registers its ML-DSA-87 key,
                     # opens an EVM window, deploys and funds the contracts → deployment.json
npm run claim -- NGT-LAG-01 2026-11-01            # reconciled → PAID
npm run claim -- NGT-LAG-01 2026-11-08 --record   # theft day → REFUSED on-chain
```
QoreChain EVM transactions need an ML-DSA-87 key and an open EVM authorisation window on the sending account. `deploy` handles both. The EVM identity is the coin-60 account from the same recovery phrase as the operator, so no new secret is created.
