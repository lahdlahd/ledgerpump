# AI usage

LedgerPump is built with an AI-native workflow. This file is kept up to date as the project grows.

## Tools

- **Claude (Anthropic):** research, architecture and code generation, used through Claude with repository access.

## Workflow

1. **Research.** Claude read the fest rules, the prize pages and the QoreChain RDK documentation. It compared the tracks by entry count, then summarised the RDK's constraints: stake size, the fact that nothing had yet run on a live rollup, the off-chain application runtime, and the withdrawal mechanics.
2. **Design.** The humans proposed the core product: reconciliation as the heart of the system, on-chain integrity, encryption and payouts. Claude tightened it into the current architecture. That covers:
   - three-way reconciliation
   - AES-256-GCM with ML-KEM-1024 key wrapping
   - a two-tier watchtower that never needs plaintext
   - withdrawals as the payout mechanism

   The humans reviewed and approved each decision, including the rule that the project uses only synthetic data and stands independent of any company.
3. **Implementation.** Claude wrote the code. The humans review it, run it and decide what ships.
4. **Verification.** Every on-chain claim must be backed by a real testnet transaction hash before it appears in the README or video.

- Choosing the track, the problem and the product.
- Architecture approval, and the constraints: an independent project and synthetic data only.
- Funding and operating the testnet rollup, reviewing all code, and recording the demo.
