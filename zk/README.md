# Zero-knowledge reconciliation

A station proves that its daily figures pass LedgerPump's three-way reconciliation (meters vs tanks, litres vs money, received vs waybill; PMS, AGO, DPK) **without revealing any figure**.

- **Circuit:** `circuits/reconcile.circom` (Groth16 on BN254, ~10.5k constraints, up to 4 pumps per product).
- **Private inputs:** every meter reading, dip, delivery, waybill quantity and price; the cash, POS and transfer totals; a secret salt.
- **Public signals:** `[commitment, reconciled, leafId]`.
  - `commitment` is a Poseidon hash of all the figures plus the salt and the station-day.
  - `reconciled` is 1 only if all seven checks pass within tolerance.
  - `leafId` is SHA-256("ledgerpump/leaf|station|date") reduced into the field.
- **Tolerances:** identical to `src/reconcile.ts`.
- **Proving time:** about 1 s per report on a laptop-class CPU.

## Checked against the engine
`npx tsx zk/scripts/check-dataset.ts` proves all 90 synthetic reports. Results: **90/90 proofs valid, 90/90 agree with the TypeScript engine**. The three planted discrepancies (theft, cash gap, short delivery) produce `reconciled = 0`.

## Trusted setup (demo only)
The Groth16 parameters were generated by the LedgerPump team: a fresh powers-of-tau (2^14) with one contribution, then one phase-2 contribution. **That is a single-party setup, fine for a testnet demo, not for production.** Production would use a public multi-party ceremony, so that no single party could forge proofs.

## Honest limits
The proof covers the figures in the commitment. It does not prove that the encrypted report (ML-KEM-1024 + AES-256-GCM) contains the same figures. That would need AES inside the circuit. The auditor tier still confirms that ciphertext and commitment match. It also can't prove that the figures typed in were true; see `docs/THREAT_MODEL.md`.
